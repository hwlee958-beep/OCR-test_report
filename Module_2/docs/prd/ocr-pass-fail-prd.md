# PRD: 시험 이미지 OCR 기반 PASS/FAIL 판정

## 1. 개요

- 배경 및 목적
  - module_1 후속 과제로, 시험 장비 화면 캡처 이미지에서 측정값을 사람이 옮겨 적는 수작업 존재
  - 수기 전사 과정의 오기·누락 및 다건 처리 시 소요 시간 발생
  - 이미지에서 측정값을 OCR로 자동 추출하고 판정 규정에 따라 PASS/FAIL을 자동 산출하는 도구 필요
  - 판정 결과를 docx 보고서로 내보내어 결과 공유 절차 단축
- 대상 사용자
  - 시험 결과 검토 담당자
  - 판정 결과 보고서 작성 담당자
  - 세부 사용자 구분 및 권한 분리 없이 단일 사용자 기준으로 동작

## 3. 기능 요구사항

### 3.1 이미지 입력

- 이미지 파일 다건 동시 업로드 지원
- 업로드 파일 목록 및 개별 파일명 표시
- 지원 이미지 형식: png, jpg 등 일반 이미지 형식
- 1회 업로드 건수는 고정하지 않으며 작업 시마다 상이
- 업로드 대상에서 개별 파일 제외 가능
- 지원하지 않는 형식·손상 파일에 대한 사유 표시 및 나머지 파일 처리 지속

### 3.2 측정값 추출

- 이미지 내 Mkr1 주파수 값 추출
- 이미지 내 Mkr1 전력 값 추출
- 추출 방식은 OCR 기반
- 이미지 레이아웃이 완전히 동일하지 않은 경우에도 측정값 항목 인식 시도
- 항목별 추출 성공·실패 상태 구분 표시
- 아래 조건 중 하나라도 해당 시 확인 필요 상태로 표시
  - 해당 항목의 값 문자열 미검출
  - 숫자·단위 형식 불일치 또는 단위 표기 누락
  - 값이 물리적으로 성립하지 않는 범위(전력 0 이하 등)
  - OCR 엔진이 보고한 문자 인식 신뢰도가 기준 미만
- 확인 필요 판단은 형식 검증을 1차 기준으로 하고 인식 신뢰도를 보조 기준으로 적용
- 인식 신뢰도 기준값: 0.60 (샘플 20장 측정 결과 정상 건 최저 0.72 기준)
- 값 일부가 가려진 이미지의 부분 인식값을 정상값으로 처리하지 않음
- 추출 실패·저신뢰 항목은 판정 전 사용자 확인 필요 상태로 표시
- 판정 대상 항목은 Mkr1 주파수·전력 2종으로 한정
- Center Freq·Span·RBW 등 화면 내 설정값은 판정 대상에서 제외

### 3.3 단위 정규화

- 주파수 표기 GHz·MHz·Hz를 동일 기준 값으로 변환하여 비교
- 전력 표기 µW·mW를 동일 기준 값으로 변환하여 비교
- 전력이 dBm으로 표기된 이미지에 대해 µW 기준으로 변환하여 비교
- dBm은 1 mW 기준 절대 단위이므로 변환에 추가 기준 정보 불요
- dBµV/m 등 상대 단위 표기만 존재하는 경우 판정 보류로 처리
- 원본 이미지에 표기된 값과 정규화된 값을 함께 표시
- 원본 표기의 소수점 자릿수 유지

### 3.4 판정

- 두 가지 판정 기준을 병행 적용하고 결과를 각각 표시
- 기준 A — 규정 문서 판정: `module_1/docs/pass-fail-rules.md` 적용
  - FREQ-01: Mkr1 주파수의 규정 범위 포함 여부
  - POWER-01: Mkr1 전력의 규정 상한 이하 여부
  - 경계값은 PASS로 판정
- 기준 B — 서식 판정: `report_template.docx` 명시 산식 적용
  - 측정값(dBµV/m) = 10·log10(µW/1000) + 107 + CF
  - 마진(dB) = Limit − 측정값, 마진 0 이상 시 PASS
  - Limit 기본값: 54 dBµV/m (960 MHz 초과 대역·측정거리 3 m, FCC Part 15 Subpart B Class B 기준, 검증 필요)
  - CF 기본값: 0 dB (무보정 기준)
  - Limit·CF는 화면에서 수정 가능하며 수정값을 판정과 보고서에 반영
- 항목별 판정 결과 및 이미지 단위 종합 판정 산출
- 종합 판정은 두 기준의 전체 항목 PASS 시에만 PASS
- 기준 A·B 결과가 상이한 경우 해당 건을 특이사항으로 구분 표시
- 전력 값이 0 이하인 경우 FAIL이 아닌 판정 보류로 처리
- 추출 실패·미보정 항목이 있는 이미지는 판정 보류로 처리
- 판정 근거로 측정값·적용 기준·비교 결과를 함께 표시
- 판정 결과에 적용된 규정 버전 기록

### 3.5 결과 확인 및 보정

- 업로드 건 전체의 판정 결과를 목록 형태로 확인
- 판정 상태(PASS·FAIL·보류)별 건수 확인
- 개별 이미지의 원본과 추출값·판정 근거 상세 확인
- 추출값 수동 수정 및 수정 후 재판정
- 수정된 값의 수동 보정 여부 표시

### 3.6 보고서 내보내기

- 판정 완료 건에 대한 docx 보고서 생성 및 다운로드
- 보고서 포함 항목은 서식의 플레이스홀더 구성을 따름
  - 머리말: 문서번호·시험일·시험명·담당자·적용 규격·시료명·보정계수(CF)
  - 판정 요약: 총 건수·PASS 건수·FAIL 건수·종합판정
  - 측정 결과: 번호·주파수(MHz)·측정전력(µW)·dBm·dBµV/m·Limit·마진·판정
  - 특이사항·작성자·검토자·생성일시
- 머리말 및 작성자·검토자 항목은 사용자가 화면에서 입력
- 적용 규격 기본값: `FCC Part 15 Subpart B Class B (3 m)`
- 문서번호는 사용자 자유 입력, 미입력 시 공란 출력
- 시험일·생성일시는 보고서 생성 시점 기준 자동 기입
- 보고서 파일명 규칙: `judgment-report_YYYYMMDD-HHMMSS.docx`
- 적용 규정 버전 및 판정 보류 건 목록은 특이사항 항목에 기재
- 기준 A·B 판정 결과가 상이한 건도 특이사항에 기재
- `module_1/data/report_template.docx` 서식을 보고서 기준 서식으로 사용
- 업로드 건 전체를 취합하여 docx 보고서 1건으로 생성
- PASS·FAIL·판정 보류 건을 모두 측정 결과 표에 포함
- 판정 요약의 PASS·FAIL 건수는 판정 보류 건을 제외하고 집계
- 원본 이미지는 보고서에 첨부하지 않음
- 서식의 표 구조·문구를 변경하지 않고 값만 채워 생성

### 3.7 이력

- 판정 결과는 서버에 저장하지 않으며 보고서 내보내기로 결과 보존
- 화면 이탈·새로고침 시 결과가 유지되지 않음을 사용자에게 안내
- 보고서에 판정 시점의 규정 버전 기록

### 3.8 백엔드 연결 확인

- 화면에서 Backend 주소 입력 및 저장
- BE 연결 확인 동작 제공
- 연결 진행 중·성공·실패 상태 표시

## 4. 비기능 요구사항

- OCR 처리 및 docx 생성은 서버 측에서 수행
- 판정 결과 영속 저장을 사용하지 않으므로 데이터베이스 미사용
- 다건 처리 중 개별 이미지 실패가 전체 처리를 중단시키지 않음
- 처리 진행 상태 및 잔여 건수 확인 가능
- 판정 결과는 동일 입력·동일 규정에서 동일하게 재현
- 시각적 표현은 `docs/DESIGN.md` 기준 준수
- 1회 처리 건수는 고정하지 않되 처리 중 진행 상태 확인 가능
- 외부 네트워크 연결 없이 로컬 환경에서 전체 기능 동작
- 판정·보고서 생성 과정에서 외부 서비스 호출 및 이미지 외부 전송 없음
